# איפיון מוצר + תוכנית עבודה — פלטפורמת ניהול חוגים ("מתחרה ל-TAZMAN")

> שם עבודה זמני למוצר: **Hugim OS** (ניתן לשינוי). מסמך זה הוא גם האיפיון המלא וגם תוכנית העבודה המפורטת ל-Claude Code.

---

## 1. Context — למה בונים את זה

הלקוח מפעיל/מכוון לשוק ניהול החוגים בישראל ורוצה לבנות **מוצר SaaS מתחרה ל-TAZMAN** (tazman.co.il), שיימכר ל**עשרות מנהלי חוגים ומעלה** — מהמדריך/מורה העצמאי ועד רשת חוגים רב-סניפית. היום השוק נשלט ע"י TAZMAN (ותיק, זול, פונקציונלי אך מיושן ב-UX), Arbox (חזק, יקר, ממוקד כושר/סטודיו), ו-Fizikal. 

הפער שאנחנו ממלאים: מוצר **מודרני, אוטומטי ומבוסס-AI**, עם **חוויית הורה/לקוח מעולה**, **אוטומציית גבייה ותקשורת**, ו**שכבת ניהול/BI** חזקה — תפור לעולם החוגים הישראלי (עברית/RTL, הוראות קבע, חשבוניות ישראל, WhatsApp).

**התוצאה הרצויה:** איפיון מלא שממנו אפשר לבנות, + roadmap מדורג ל-Claude Code שמוביל מ-MVP מוכר-לקוחות ועד פלטפורמה מלאה.

### הערה חשובה על הקלט
"טיוטת האיפיון" שהלקוח ציין כמצורפת **לא הגיעה** אל הסביבה (הריפו ריק, אין קובץ). האיפיון כאן נבנה מאפס על בסיס מחקר TAZMAN/Arbox/Fizikal, הדרישות הפיסקליות בישראל, וראיון עם הלקוח. **אם קיימת טיוטה — יש לשתף אותה ולמזג לפני תחילת בנייה.**

### החלטות שהתקבלו בראיון
- קהל יעד: פלטפורמה למנהל חוג יחיד ועד מנהל רשת חוגים; נמכרת כ-SaaS לעשרות עסקים ומעלה (multi-tenant).
- סטאק: לבחירת הצוות → **Next.js + Supabase + Vercel** (PWA, לא נייטיב בשלב א').
- בידול מרכזי (סדר השקעה): (1) חוויית הורה/לקוח, (2) אוטומציה ו-AI, (3) ניהול/דוחות/BI. לא מתחרים על מחיר.
- תשלומים: שלב א' = אינטגרציה לסולק + ספק חשבוניות חיצוני; שלב ב' = חשבוניות מובנות (מודל "חשבוניות ישראל" / מספר הקצאה).

## 2. חזון מוצר ומיצוב

**One-liner:** "מערכת ההפעלה לעסק החוגים — רישום, גבייה ותקשורת על טייס אוטומטי, עם חוויית הורה שאוהבים."

**עקרונות מנחים:**
1. **Automation-first** — כל פעולה חוזרת (גבייה, תזכורת, השלמה, רשימת המתנה, חידוש) רצה לבד; המנהל מטפל בחריגים בלבד.
2. **Parent-love** — ההורה נרשם ומשלם ב-60 שניות מהנייד, רואה הכל, לא צריך להתקשר לאף אחד.
3. **Israel-native** — RTL, עברית, הוראות קבע, חשבוניות ישראל/מספר הקצאה, WhatsApp כערוץ ראשי.
4. **AI as a teammate** — סוכן שעונה להורים, מסכם למנהל, חוזה נטישה, ומציע פעולות.
5. **Scales with the customer** — אותו מוצר משרת עצמאי בודד ורשת של 20 סניפים (הרשאות, סניפים, איחוד/הפרדת גבייה).

**מיצוב מול מתחרים:**
| ממד | TAZMAN | Arbox | **אנחנו** |
|---|---|---|---|
| UX/מודרניות | נמוך | בינוני-גבוה | **גבוה, מובייל-first** |
| מחיר | זול | יקר | **אמצע, שקוף** |
| אוטומציה/AI | מועט | חלקי | **ליבה של המוצר** |
| חווית הורה | בסיסית | טובה | **מצוינת (PWA, WhatsApp)** |
| התאמה לחוגים IL | גבוהה | בינונית | **גבוהה** |

## 3. פרסונות ותפקידים

- **בעל/מנהל עסק חוגים (Owner/Admin)** — רואה הכל, מגדיר חוגים, תמחור, גבייה, דוחות.
- **מנהל סניף/רשת (Branch/Network Manager)** — תת-ארגון; רואה רק את הסניף/ים שלו (בגרסת רשת).
- **מזכירה/תפעול (Staff)** — רישום, נוכחות, תקשורת, גבייה — ללא גישה לרווחיות/הגדרות רגישות.
- **מדריך/מורה (Instructor)** — אפליקציית מדריך: הלוח שלי, נוכחות, הערות, תקשורת עם הורי הקבוצה.
- **הורה/לקוח (Parent/Client)** — אפליקציית הורה: ילדים, מערכת שעות, תשלומים, מסמכים, הודעות, ביטול/השלמה.
- **חניך בוגר (Adult Member)** — לקוח = גם המשתתף (יוגה/כושר/מבוגרים).
- **Super-Admin (שלנו)** — ניהול כלל ה-tenants, חיוב SaaS, תמיכה, flags.

## 4. איפיון פונקציונלי — מודולים (ה"פיצ'רים המרכזיים")

> כל מודול מתואר כ-capabilities. סימון **[MVP]** = חובה לגרסה המוכרת הראשונה; **[P2]/[P3]** = גלים הבאים.

### 4.1 CRM — לקוחות, משפחות, לידים
- **[MVP]** כרטיס לקוח/תלמיד: פרטים, אנשי קשר, הורים/מבוגר אחראי, בריאות/אלרגיות/הערות, תגיות.
- **[MVP]** מבנה **משפחה** (מספר ילדים → הורה אחד משלם), חיוב מאוחד לכל המשפחה.
- **[MVP]** היסטוריה מלאה: הרשמות, תשלומים, נוכחות, תקשורת, מסמכים — ב-timeline אחד.
- **[MVP]** ניהול **לידים** + pipeline בסיסי (מתעניין → ניסיון → נרשם), מקורות ליד.
- **[P2]** דה-דופ/מיזוג כפילויות, ייבוא מ-Excel/TAZMAN, שדות מותאמים.

### 4.2 קטלוג — חוגים, קבוצות, סניפים
- **[MVP]** היררכיה: **סניף/מיקום → חדר → חוג (course) → קבוצה/מחזור (group) → שיעור (session)**.
- **[MVP]** הגדרת חוג: קטגוריה, תיאור, גילאים/רמות, מדריך, קיבולת, עונת פעילות (שנה"ל/קיץ), מחיר ברירת-מחדל.
- **[MVP]** קבוצה: ימים/שעות, מדריך משובץ, קיבולת, תאריכי התחלה/סיום, מיקום/חדר.
- **[P2]** רמות/מסלולי התקדמות, תנאי קדם, קורסים מרובי-שלבים, חבילות (bundle של כמה חוגים).

### 4.3 מערכת שעות ולוח שנה (Scheduling)
- **[MVP]** מחולל **שיעורים חוזרים** (RRULE): יצירת כל ה-sessions לעונה אוטומטית.
- **[MVP]** לוח שנה (יום/שבוע/חודש), תצוגות לפי סניף/מדריך/חדר, זיהוי **התנגשויות** (חדר/מדריך).
- **[MVP]** חריגים: חגים/חופשות, ביטול שיעור, דחייה, שיעור חד-פעמי.
- **[MVP]** **שיעורי השלמה (makeup)**: תלמיד שהחסיר משבץ עצמו לשיעור מקביל פנוי.
- **[MVP]** **שיעורי ניסיון (trial)**: שיבוץ חד-פעמי עם המרה להרשמה.
- **[P2]** ניהול חדרים/משאבים מתקדם, אופטימיזציית שיבוץ מבוססת-AI, סנכרון Google Calendar למדריכים.

### 4.4 הרשמה אונליין וטפסים דיגיטליים (Registration) — *בידול ליבה*
- **[MVP]** **עמוד הרשמה לחוג** ציבורי (לינק/QR/widget להטמעה באתר) — מיתוג לפי tenant.
- **[MVP]** זרימת הרשמה בנייד ב-60 שניות: בחירת חוג → פרטי ילד → טפסים → תשלום → אישור (WhatsApp/מייל).
- **[MVP]** **טפסים דיגיטליים**: הצהרת בריאות, ויתור/תקנון, אישור צילום — עם **חתימה דיגיטלית** ושמירת PDF.
- **[MVP]** בדיקת **קיבולת** בזמן אמת + **רשימת המתנה (waitlist)** עם קידום אוטומטי כשמתפנה מקום.
- **[P2]** שאלונים מותאמים per-חוג, קודי הרשמה/הנחה, הרשמה קבוצתית (כמה ילדים בבת אחת), חידוש עונה בקליק.

### 4.5 נוכחות (Attendance)
- **[MVP]** סימון נוכחות מהיר לכל שיעור (מהאפליקציה של המדריך), סימון המוני, "נעדר/נוכח/השלמה".
- **[MVP]** **כרטיסיות (punch cards)**: ניכוי אוטומטי של כניסה בכל נוכחות, יתרה, תפוגה.
- **[MVP]** **check-in** ע"י HORE/חניך (QR בכניסה / קוד שיעור).
- **[P2]** התראות היעדרות רצופה (risk), דוח נוכחות למוסד ("יומן ירוק" דיגיטלי), נוכחות לפי GPS/geofence.

### 4.6 גבייה ותשלומים (Billing & Payments) — *בידול ליבה*
- **[MVP]** מודלי תמחור: **מנוי חודשי**, **כרטיסייה**, **תשלום חד-פעמי/עונתי**, פריסה ל-N תשלומים.
- **[MVP]** **הוראת קבע / טוקניזציה** של כרטיס אשראי דרך הסולק (לא שומרים PAN — PCI SAQ-A).
- **[MVP]** **מנוע חיוב אוטומטי** (billing run) חודשי: יוצר חיובים, סולק, מפיק חשבונית, מעדכן יתרה.
- **[MVP]** **Dunning** — טיפול בכשלי חיוב: ניסיון חוזר, התראת WhatsApp להורה עם לינק לעדכון כרטיס, אסקלציה למנהל.
- **[MVP]** הנחות, קופונים, **מלגות/סבסוד** (סכום/אחוז), הנחת אח/משפחה, זיכויים/החזרים.
- **[MVP]** יתרות חוב, גיול חובות, לינק תשלום אישי (pay-link) ב-WhatsApp.
- **[P2]** ארנק/קרדיט ללקוח, תשלום בהעברה בנקאית/ביט, תשלומים חלקיים, מחירון דינמי לפי מילוי.

### 4.7 חשבוניות ומיסוי (Invoicing) — *ספציפי ישראל*
- **[MVP — שלב א']** אינטגרציה ל**ספק חשבוניות** (חשבונית ירוקה/Morning, iCount, invoice4u): הפקת חשבונית/קבלה אוטומטית, שהספק מטפל ב**מספר הקצאה** מול רשות המסים.
- **[P2 — שלב ב']** מנוע חשבוניות **מובנה** עם חיבור ישיר ל**מודל "חשבוניות ישראל"** (API רשות המסים לקבלת מספר הקצאה). *שים לב לספי החובה: 25K (5/2024) → 20K (2025) → 10K (1/2026) → 5K (6/2026). רוב חיובי החוגים נמוכים מהסף, אך התכנון חייב לתמוך.*
- **[MVP]** התאמת ספרים בסיסית, ייצוא לרו"ח (CSV/קובץ אחיד/מבנה מרכבה בהמשך).

### 4.8 תקשורת ואוטומציה (Communications) — *בידול ליבה*
- **[MVP]** **WhatsApp Business API** (דרך BSP: 360dialog/Twilio) — ערוץ ראשי: אישורי הרשמה, תזכורות שיעור, התראות גבייה, pay-links, הודעות יזומות.
- **[MVP]** SMS (ספק IL: InforU/019) ו-Email (Resend/SES) כגיבוי/תוספת.
- **[MVP]** **תבניות הודעה** (templates) מאושרות + משתנים (שם ילד, חוג, סכום, לינק).
- **[MVP]** **אוטומציות מבוססות-triggers**: "נרשם → שלח ברוכים הבאים", "חיוב נכשל → תזכורת", "נעדר 3 פעמים → התראה", "עונה מסתיימת → הצעת חידוש".
- **[P2]** קמפיינים/דיוור קבוצתי מפולח, inbox דו-כיווני (שיחות WhatsApp במערכת), NPS/משוב.

### 4.9 אפליקציית הורה/לקוח (PWA) — *בידול ליבה*
- **[MVP]** התחברות (OTP בוואטסאפ/SMS), דשבורד: ילדים, מערכת שעות השבוע, חיובים קרובים.
- **[MVP]** תשלומים: אמצעי תשלום, חיובים/חשבוניות להורדה, עדכון כרטיס, תשלום חוב.
- **[MVP]** מסמכים חתומים, הודעות מהעסק, הרשמה לחוג נוסף/חידוש.
- **[MVP]** **ביטול/דיווח היעדרות + שיבוץ השלמה** עצמאי.
- **[P2]** push notifications, צ'אט עם המדריך/עסק, הזמנת חברים (referral).

### 4.10 אפליקציית מדריך (PWA)
- **[MVP]** "הלוח שלי" (שיעורים היום/השבוע), רשימת חניכים, **סימון נוכחות**, הערות לשיעור.
- **[MVP]** פרטי קשר של הורי הקבוצה, שליחת הודעה לקבוצה.
- **[P2]** דוח שעות/שכר אישי, החלפות/היעדרויות מדריך, חומרי שיעור.

### 4.11 שכר מדריכים (Instructor Payroll)
- **[P2]** מודלי שכר: לפי שעה / לפי שיעור / לפי מספר חניכים / אחוז מהכנסה.
- **[P2]** חישוב חודשי אוטומטי מהנוכחות/לוח, דוח לתשלום, אישור מנהל.

### 4.12 דוחות ו-BI — *בידול ליבה*
- **[MVP]** **דשבורד מנהל**: הכנסות חודש, חיובים שנכשלו, הרשמות חדשות, נוכחות, מילוי חוגים.
- **[MVP]** דוחות גבייה (צפוי מול בפועל, חובות), דוח הרשמות, דוח נוכחות, רשימות חוג.
- **[P2]** **BI**: תחזית הכנסות, **churn/שימור**, רווחיות per-חוג (הכנסה פחות שכר מדריך), LTV, מקורות גיוס, ניצולת חדרים.
- **[P2]** ייצוא/שיתוף דוחות, דוחות מתוזמנים במייל.

### 4.13 שכבת AI — *בידול ליבה* (Claude API)
- **[P2]** **סוכן שירות להורים** (WhatsApp/צ'אט): עונה על "מתי השיעור?", "כמה אני חייב?", "איך מבטלים?", מבצע פעולות מורשות (שיבוץ השלמה, pay-link) עם guardrails.
- **[P2]** **סיכומי מנהל** ("מה קרה השבוע", "למה ההכנסות ירדו") בשפה טבעית.
- **[P2]** **חיזוי churn** + המלצת פעולה; זיהוי חוגים בסיכון.
- **[P3]** אופטימיזציית שיבוץ/רשימות המתנה, ניסוח הודעות/תבניות, תמחור מומלץ.

### 4.14 מיני-אתר / נוכחות ציבורית
- **[P2]** עמוד עסק ציבורי + עמודי חוגים, קטלוג להרשמה, widget להטמעה, SEO בסיסי, סנכרון לפייסבUK (כמו TAZMAN).

### 4.15 הגדרות, הרשאות, רב-דיירות
- **[MVP]** ניהול משתמשים ותפקידים (RBAC), מיתוג per-tenant (לוגו/צבעים/שם), הגדרות עסק/מיסוי/ערוצים.
- **[MVP]** **בידוד נתונים מלא בין tenants** (Supabase RLS).
- **[MVP]** אשף **onboarding** (הקמת עסק ב-10 דקות: סניף→חוגים→תמחור→ערוצים→לינק הרשמה).

### 4.16 שכבת ה-SaaS שלנו (מכירה לעסקים)
- **[MVP]** הרשמת עסק חדש, חבילות/תמחור שלנו, **חיוב ה-SaaS** שלנו (Stripe/סולק), trial.
- **[MVP]** **Super-admin console**: ניהול tenants, מדדי שימוש, תמיכה, impersonation מבוקר, feature flags.
- **[P2]** billing מדורג לפי מספר תלמידים/הודעות, חיוב usage (WhatsApp).

## 5. ארכיטקטורת מידע ומודל נתונים (רמת-על)

**Multi-tenant:** כל טבלה נושאת `tenant_id`; בידוד ב-**RLS** לפי ה-JWT של Supabase Auth (claim `tenant_id` + `role`). Super-admin עוקף דרך service-role בלבד בצד שרת.

ישויות ליבה (Postgres):
- `tenants`, `users`, `memberships` (user↔tenant + role + branch scope), `branches`, `rooms`
- `contacts` (הורה/מבוגר), `families`, `students` (student↔family), 
- `courses`, `groups` (מחזור), `sessions` (שיעור בודד, נוצר מ-RRULE), `enrollments` (student↔group)
- `attendance` (enrollment↔session + status), `punch_cards`, `waitlist_entries`, `makeups`
- `pricing_plans`, `subscriptions` (enrollment↔plan), `invoices_charges` (חיוב צפוי), `payments`, `payment_methods` (token בלבד), `discounts`, `credits`
- `documents` (טפסים חתומים + PDF ב-Storage), `form_templates`
- `messages`, `message_templates`, `automations` (trigger→action), `conversations`
- `leads`, `instructors` (+ `payroll_rules`), `reports_snapshots`
- `audit_log`, `webhooks_inbox` (אירועי סולק/חשבוניות/WhatsApp — idempotent)

**עקרונות:** money ב-minor units (אגורות, integer); timezone `Asia/Jerusalem`; כל חיוב/תשלום/הודעה עם מצב (state machine) + audit. Webhooks חיצוניים → `webhooks_inbox` עם idempotency key.

## 6. ארכיטקטורה טכנית

**Frontend**
- **Next.js (App Router) + TypeScript**, Tailwind CSS עם **RTL/logical properties**, **shadcn/ui** + Radix.
- אזורים: `admin/` (מנהל), `parent/` (הורה PWA), `instructor/` (מדריך PWA), `public/` (הרשמה), `super/` (super-admin).
- i18n עברית ברירת-מחדל (מבנה מוכן לאנגלית/ערבית). טפסים: react-hook-form + zod. דאטה: TanStack Query. גרפים: Recharts (ראה skill `dataviz`).

**Backend / Data**
- **Supabase**: Postgres + **RLS** (multi-tenancy), Auth (OTP/SMS/WhatsApp + email), Storage (PDF/מסמכים), Realtime (לוח/נוכחות/inbox).
- לוגיקה עסקית: Next.js Route Handlers / Server Actions + **Supabase Edge Functions** לאינטגרציות וחתימת webhooks.
- **עבודות רקע ותזמון**: billing run, dunning, reminders, waitlist, session-generation — דרך Supabase Cron + טבלת queue, או **Inngest/Trigger.dev** (מומלץ ל-retries/observability). החלטה ב-M1.

**אינטגרציות (Adapter pattern — ממשק אחיד + מימושים)**
- **Payments/סליקה**: `PaymentProvider` → מימושים ל-Tranzila / Cardcom / PayPlus / Meshulam (טוקניזציה, חיוב, זיכוי, 3DS, webhooks). מתחילים בספק אחד (לבחירה), מרחיבים.
- **Invoicing**: `InvoiceProvider` → חשבונית ירוקה/Morning (שלב א'); מימוש `IsraelTaxDirect` למספר הקצאה (שלב ב').
- **Messaging**: `MessageChannel` → WhatsApp (BSP), SMS (IL), Email. ניהול תבניות ו-opt-in.
- **AI**: Claude API (Anthropic) — טוען skill `claude-api` לפרטי מודלים/תמחור לפני אינטגרציה. סוכן עם tool-use ל-pay-link/שיבוץ השלמה (guardrails + אישור).

**Infra / Quality**
- פריסה: **Vercel** (frontend + API) + Supabase managed. Env/secrets ב-Vercel + Supabase Vault.
- בדיקות: **Vitest** (unit/לוגיקה עסקית — במיוחד billing/RRULE/RLS), **Playwright** (E2E: הרשמה→תשלום, billing run). CI ב-GitHub Actions.
- Observability: Sentry + לוגים; `audit_log` לפעולות רגישות.

## 10. דרישות לא-פונקציונליות

- **אבטחה/פרטיות**: RLS לכל טבלה; הצפנה at-rest/in-transit; **מינימום מידע על קטינים**; עמידה ב**חוק הגנת הפרטיות (תיקון 13)**; הסכמות/opt-in לתקשורת; audit log; least-privilege; impersonation מתועד.
- **PCI**: לא שומרים מספרי כרטיס — טוקניזציה אצל הסולק (SAQ-A). 3DS היכן שנדרש.
- **ביצועים**: עומסי billing run / הודעות בתורים עם rate-limit; לוח שנה ודוחות עם pagination/indexing.
- **אמינות**: webhooks idempotent; retries מבוקרים; גיבויי DB; תצפיתיות (Sentry/לוגים/מטריקות).
- **נגישות**: WCAG 2.1 AA; RTL מלא; מובייל-first.

## 11. אימות (Verification) כולל

1. **E2E מסע-הזהב** (Playwright): עסק נרשם → מקים חוג+תמחור → מפרסם לינק → הורה נרשם בנייד → חותם טפסים → מקים הוראת קבע → billing run מחייב → חשבונית מופקת → תזכורת WhatsApp → מדריך מסמן נוכחות → דשבורד מציג הכל.
2. **Unit** (Vitest): לוגיקת כסף (אגורות/עיגול/מע"מ/הנחות), RRULE+חריגים, state machines (חיוב/תשלום/dunning), חישובי דוחות.
3. **RLS/אבטחה**: בדיקות שדיירים לא רואים זה את זה; super-admin מבוקר; סריקת אבטחה (skill `security-review`).
4. **אינטגרציות**: sandbox של הסולק/ספק החשבוניות/WhatsApp; בדיקות webhook idempotency.
5. **הרצה אמיתית**: skill `run` להרמת האפליקציה ובדיקת זרימות ידנית לכל milestone.

## 12. סיכונים ושאלות פתוחות

- **טיוטת האיפיון המקורית לא התקבלה** — יש לשתף ולמזג לפני M0.
- **בחירת ספקים**: איזה סולק ראשון (Tranzila/Cardcom/PayPlus/Meshulam)? איזה ספק חשבוניות? איזה BSP ל-WhatsApp? (נדרשים חשבונות sandbox/מפתחות — דרך הגדרות הסביבה/secrets).

- **המרת ה-egress proxy** בסביבה חוסם אתרים ישראליים — מחקר מתחרים מעמיק נוסף יתבצע מחוץ לסביבה או דרך ספקי scraping אם יידרש.
